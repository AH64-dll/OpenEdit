# Detailed Analysis: 30ms Audio Micro-Fades in MLT Emitter (Milestone 1 / R1)

## Executive Summary
This report presents a thorough, read-only architectural investigation of `open_edit/render/emitter.py` and its test suites (`tests/test_render/test_emitter.py` and `tests/test_emitter.py`). The objective is to establish the precise technical strategy for automatically injecting 30ms audio micro-fades (gain ramp-in at clip start and gain ramp-out at clip end) on clip boundaries when emitting MLT XML to eliminate audio clicks and pops.

---

## 1. Audio Properties & Filter Attachment Mechanism in `emitter.py`

### 1.1 Document Hierarchy & Entry Generation
In `open_edit/render/emitter.py`, the main entry point is `emit_timeline(timeline, config, asset_paths)` (lines 79-182).

The MLT XML tree structure generated by `emitter.py` is as follows:
```xml
<mlt LC_NUMERIC="C" version="7.22.0">
  <profile width="1920" height="1080" frame_rate_num="30" frame_rate_den="1" ... />
  
  <!-- Asset Producers -->
  <producer id="producer_{asset_hash}" resource="/path/to/media.mp4" />
  
  <!-- Tractor & Multitrack -->
  <tractor id="tractor0" out="60">
    <multitrack>
      <track producer="playlist_{track_id}" />
    </multitrack>
  </tractor>

  <!-- Track Playlist -->
  <playlist id="playlist_{track_id}">
    <blank length="30" /> <!-- If gap exists before clip -->
    <entry producer="producer_{asset_hash}" in="0" out="60">
      <!-- Clip-level filters and transitions are child tags of <entry> -->
      <filter id="e1" service="volume">
        <property name="gain">0.5</property>
      </filter>
    </entry>
    <!-- Track-level filters are child tags of <playlist> -->
    <filter id="e2" service="volume">...</filter>
  </playlist>
</mlt>
```

### 1.2 How Filters are Attached to Playlist Clip Entries
Filter emission is performed by `_emit_filter(parent, effect, fps_num, fps_den)` (lines 31-57):
1. `parent` is the `etree._Element` representing either a clip `<entry>` (lines 157-166) or a track `<playlist>` (lines 169-173).
2. For clip-level filters, `parent` is the `<entry>` element.
3. Keyframes are attached as child elements `<kf frame="..." value="..." interp="...">` under the `<filter>` element.
4. Filter scope: When a `<filter>` element is placed inside `<entry>`, MLT limits its execution strictly to that clip's temporal playback window (from frame `0` to frame `out - in`).

**Key Architectural Insight**: Producer-level filter chains are not used in `emitter.py`. Filters and micro-fades must be attached directly to playlist clip `<entry>` elements, ensuring that every clip instance (even if sharing a producer asset) receives micro-fades relative to its own local cut boundaries.

## 2. MLT Filter Names & Properties for Audio Volume Fades

### 2.1 Standardized Filter Service in `open_edit`
In `open_edit/ir/catalog/effects/volume.yaml`, the standard volume effect is configured as:
- `name`: `volume`
- `mlt_service`: `volume`
- `params`: `gain` (linear scale, default 1.0)
- `keyframe_params`: `[gain]`

MLT's `volume` service with keyframes (`<kf>`) is the official, catalog-backed mechanism in `open_edit`.

### 2.2 XML Keyframe Representation for Micro-Fades
For a micro-fade filter, keyframes set linear gain transitions:
```xml
<filter id="microfade_{clip_id}" service="volume">
  <kf frame="0" value="0.0" interp="linear" />
  <kf frame="{fade_in_frames}" value="1.0" interp="linear" />
  <kf frame="{fade_out_start_frame}" value="1.0" interp="linear" />
  <kf frame="{total_clip_frames}" value="0.0" interp="linear" />
</filter>
```

### 2.3 Cascading Multiplier Behavior with User Filters
In MLT XML, multiple `<filter>` tags on an `<entry>` execute in series (cascade signal flow):
- Output Signal = Input Audio $\times$ Micro-fade Gain $M(t) \times$ User Gain $G_{\text{user}}(t)$.
- **Unity Gain Clip**: $M(t) \times 1.0 = M(t)$ (ramps from 0.0 to 1.0 in 30ms, holds at 1.0, ramps to 0.0 in last 30ms).
- **Custom Gain Clip (e.g. gain=0.5)**: $M(t) \times 0.5$ (ramps from 0.0 to 0.5 in 30ms, holds at 0.5, ramps to 0.0 in last 30ms).
- **Muted Clip (gain=0.0)**: $M(t) \times 0.0 = 0.0$ (remains completely silent throughout).

This cascading property guarantees that automatic micro-fades compose seamlessly with user volume effects without overwriting user settings.

## 3. Clip Boundary Handling & 30ms Frame Conversion

### 3.1 Timecode & Frame Calculation Rules in `emitter.py`
In `emitter.py`, conversion from seconds to frame indices uses `_format_timecode()`:
$$\text{frames} = \text{int}\left(\text{round}\left(seconds \times \frac{fps\_num}{fps\_den}\right)\right)$$

For a clip:
- `clip_dur = clip.out_point_sec - clip.in_point_sec`
- `total_frames = int(round(clip_dur * fps_num / fps_den))`

### 3.2 30ms Conversion across Frame Rates
Target micro-fade duration: $T_{\text{fade}} = 0.030\text{ seconds}$ (30ms).

$$\text{fade\_frames\_raw} = \text{int}\left(\text{round}\left(0.030 \times \frac{fps\_num}{fps\_den}\right)\right)$$
$$\text{fade\_frames} = \max(1, \text{fade\_frames\_raw})$$

| Frame Rate (FPS) | Raw Formula ($0.030 \times \text{FPS}$) | Calculated Fade Frames | Actual Fade Duration (ms) |
|---|---|---|---|
| **30 fps** | $0.030 \times 30 = 0.90$ | **1 frame** | 33.3 ms |
| **60 fps** | $0.030 \times 60 = 1.80$ | **2 frames** | 33.3 ms |
| **25 fps** | $0.030 \times 25 = 0.75$ | **1 frame** | 40.0 ms |
| **24 fps** | $0.030 \times 24 = 0.72$ | **1 frame** | 41.7 ms |

### 3.3 Boundary & Edge Case Clamping Rules
For short clips (duration $< 60\text{ms}$), 30ms fade-in and 30ms fade-out windows would overlap or exceed total clip duration.

1. **Max Fade Limit**: $\text{actual\_fade\_frames} = \min(\text{fade\_frames},\, \text{total\_frames} // 2)$.
2. **Zero / Single Frame Clips**:
   - If $\text{total\_frames} \le 1$: Skip micro-fade injection (cannot build a 2-point ramp).
3. **Keyframe Deduplication**:
   - Store keyframes as `(frame_number, value)`.
   - If $\text{fade\_out\_start\_frame} == \text{fade\_in\_frames}$ (e.g. a 2-frame clip with 1-frame fade-in and 1-frame fade-out), only emit a single keyframe at frame `1` with value `1.0` (forming a triangular peak envelope `0.0 -> 1.0 -> 0.0`).

## 4. XML Output Verification Strategy

### 4.1 Verification Method
To verify emitted micro-fades:
1. Parse generated XML string using `lxml.etree.fromstring(xml_str)`.
2. Locate clip entries: `entries = root.xpath("//playlist/entry")`.
3. Check for micro-fade filter: `filters = entry.xpath("filter[@service='volume']")`.
4. Inspect keyframes under the filter: `kfs = filter.xpath("kf")`.
5. Verify keyframe frame numbers and linear gain values:
   - First keyframe: `frame="0"`, `value="0.0"`, `interp="linear"`.
   - Second keyframe: `frame="{fade_in_frames}"`, `value="1.0"`, `interp="linear"`.
   - Third keyframe: `frame="{total_frames - fade_in_frames}"`, `value="1.0"`, `interp="linear"`.
   - Fourth keyframe: `frame="{total_frames}"`, `value="0.0"`, `interp="linear"`.

### Step 2: Add `_emit_audio_micro_fade` Helper Function in `emitter.py`
```python
def _emit_audio_micro_fade(
    entry: etree._Element,
    clip_id: str,
    clip_dur_sec: float,
    fps_num: int,
    fps_den: int,
    fade_duration_sec: float = 0.030,
) -> None:
    """Inject automatic 30ms audio micro-fade volume filter into clip entry."""
    if clip_dur_sec <= 0.0:
        return

    fps = fps_num / fps_den
    total_frames = int(round(clip_dur_sec * fps))
    if total_frames <= 1:
        return

    fade_frames = max(1, int(round(fade_duration_sec * fps)))
    fade_frames = min(fade_frames, total_frames // 2)
    if fade_frames <= 0:
        return

    filter_el = etree.SubElement(entry, "filter", attrib={
        "id": f"microfade_{clip_id}",
        "service": "volume",
    })

    fade_out_start = total_frames - fade_frames
    kf_specs = [
        (0, "0.0"),
        (fade_frames, "1.0"),
        (fade_out_start, "1.0"),
        (total_frames, "0.0"),
    ]

    seen_frames = set()
    for frame_idx, val in kf_specs:
        if frame_idx not in seen_frames:
            seen_frames.add(frame_idx)
            etree.SubElement(filter_el, "kf", attrib={
                "frame": str(frame_idx),
                "value": val,
                "interp": "linear",
            })
```

### Step 3: Invoke Helper in `emit_timeline` (`emitter.py:162`)
