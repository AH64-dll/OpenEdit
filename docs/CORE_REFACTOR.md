# Core editor reassessment and implementation

OpenEdit now makes the playhead playable before completing the rest of a timeline,
retrieves small timestamped media references through one query, and uses compact
AI instructions with operation help on demand. The editor puts media, video,
AI instructions and contextual controls above a shared timeline. This changes
runtime loading, context delivery and preview invalidation, rather than only styling.

## Component decisions

| Component | Decision | Reason and implemented result |
|---|---|---|
| IR, precise time conversion and validation | Keep | Deterministic edits and frame timing belong to the application. Atomic batches remain available for arbitrary AI strategies. |
| Content-addressed media and SQLite history | Keep | Required for recovery, Undo/Redo, reopening and source integrity. No stored project format was removed. |
| Tool registry and specialist implementations | Simplify | Six public interfaces remain; specialized implementations load only on use. Removed eager imports and the custom mapping abstraction in favor of ordinary callable dictionary entries. |
| Mandatory AI manuals and ordered editing rules | Remove | Removed duplicated tool/IR essays, mandatory search-before-generation, style prerequisites and fixed tool sequencing from default prompts. Models choose the strategy. |
| MCP and built-in agent startup guidance | Consolidate | Share a concise bootstrap. Operation signatures/help and the Python IR API are retrieved with `query_project describe`. Built-in prompts no longer repeat the full schemas or project dumps. |
| Video inspection, visual references and transcript paging | Consolidate | `inspect_media` returns exact source sample timestamps, one contact sheet and range-filtered transcript metadata. MCP and built-in SDK adapters receive actual image content. |
| Media inspection cache | Keep / simplify | Immutable source identity plus requested timestamps identify the sheet. Limit frames to 12 and words to 500; retain at most 64 sheets per source. Use frames=0 for text-only retrieval. |
| Narrative helpers, style memory, stock search and generators | Simplify | Available on demand; no compulsory tool chain or default startup loading. They remain useful for some tasks and existing clients. |
| Editable graphics and captions | Keep | Titles, overlays and animations remain editable and share history/rendering. Browser tests verify interactive/export parity. |
| HyperFrames and Remotion engines | Keep as compatibility | Excluded from normal setup/loading. Existing graphs retain replay support. A replacement would need migration and output equivalence evidence. |
| FFmpeg and MLT render engine | Keep | Existing actual-media tests prove cuts, transitions, effects, audio and color parity. Replacing it would add migration risk without measured benefit in this task. |
| Preview scheduling | Replace | A short playhead range runs first, with incremental completed-chunk playback and background fill. New seeks prioritize missing ranges; stale project/revision work cannot replace current playback. |
| Global snapshot deletion on edit | Replace | Retain up to 32 graph-hash snapshots. A normal edit or Undo/Redo compares old and new timeline slices instead of destroying the evidence required for localized invalidation. Legacy destructive log ordering still clears derived snapshots. |
| Partially generated preview revisions | Fix | Unchanged keys no longer hide missing artifacts. Background work fills ranges not generated by the initial focused request. |
| CPU/GPU selection and worker cancellation | Simplify / fix | CPU rendering skips the GPU decode benchmark. Graphics workers close and reap Chromium before forced group termination. |
| Editor presentation | Consolidate | One primary Edit view, a library selector, a durable AI instruction box and contextual editing controls. Graphics is an explicit action; source editing and quality checks are secondary. Export is in the top bar. |
| Redundant UI controls and font network requests | Remove | Removed redundant top-bar toggles, duplicate export placement, specialized note buttons and external font requests. Mobile playback omits the secondary volume slider. |
| Durable render jobs, stale-write checks and export verification | Keep | Essential reliability controls, rather than instructions restricting creative decisions. |
| Built-in OpenCode editing | Fix | Connect the selected project through native MCP; record calls/results without executing mutations twice. The editing agent receives the composable application interfaces instead of generic repository browsing. |
| Graphics reuse across frozen exports | Fix | Retain verified, content-addressed graphics and derived CAS bytes across snapshot cleanup. Capture only caches for graphics referenced by the frozen timeline; preserve independent snapshot bytes and keep derived cache out of the import library. |

## Measured results

Full machine-readable measurements: [CORE_REFACTOR_METRICS.json](CORE_REFACTOR_METRICS.json).

| Measurement | Before | After |
|---|---:|---:|
| Serialized six-tool schema characters | 11,080 | 5,305 (52% smaller) |
| MCP bootstrap characters | 1,209 | 521 (57% smaller) |
| Built-in prompt for the same small summary state | 16,607 | 918 (94% smaller) |
| Initial visible desktop buttons at 1440×900 | 39 | 23 (41% fewer) |
| Chunks regenerated after a local trim in the 8-chunk fixture | 8 | 4 |

These are prompt payload measurements, not provider billing or image-token counts.
The original prompt builder and UI were read from the checked-out Git HEAD for
comparison; no extra checkout or worktree was created.

Actual runs on this machine:

- Four timestamped source frames: 0.360 s cold, about 0.4 ms cached.
- Range transcript: 10 relevant words instead of the fixture's full 40.
- First playable browser preview of a 12-second timeline: 1.870 s. The first
  request covers 0–6 seconds; the remainder fills in the background.
- Cached browser seek to 11 seconds: 35 ms; frame stepping verified at 30 fps.
- Eight-second 1080p CPU export: 5.592 s in the recorded fixture run; full decode
  verification passed, with both audio and video measuring 8.000 s.
- Cached preview: zero processed chunks. Partial range generation followed by
  background fill is checked explicitly; a partial manifest is not counted as
  complete just because a job exits successfully.

## Validation and reproduction

Use the existing checkout and activate `.venv`. For this cloud container:

```bash
cd /workspace/OpenEdit
source .venv/bin/activate
export OPEN_EDIT_CHROMIUM=/usr/bin/chromium
export OPEN_EDIT_CHROMIUM_NO_SANDBOX=1
export OPEN_EDIT_RENDER_BACKEND=cpu
export OPEN_EDIT_SOURCE_PROXY_AUTO=0
export QT_QPA_PLATFORM=offscreen
export SDL_VIDEODRIVER=dummy
export SDL_AUDIODRIVER=dummy
ruff check open_edit tests tools/benchmark_core.py
env -u OPEN_EDIT_SOURCE_PROXY_AUTO pytest -m 'not browser' --timeout=90 --timeout-method=thread --tb=short
node tests/browser/editor-core.cjs
node tests/browser/studio.cjs
node tests/browser/authoring.cjs
python tools/benchmark_core.py --output /tmp/core-metrics.json
python -m build
```

The browser scripts require the locked `tests/browser` npm dependencies. Ordinary
Python/MCP startup does not install browsers or download optional render engines.
The Chromium setting is specific to this isolated cloud container.

Coverage includes actual stdio MCP image delivery; exact red/blue sample times;
range transcript paging without video decoding; source cache reuse after reopen;
partial preview completion; preservation of unchanged chunks after trimming;
region selection; manual clip moves/trims; graphics, animation, effects and
transition controls; shared action history; project reopen; color and interactive
canvas/export parity; verified local exports; responsive desktop/mobile editing;
and cancellation without a surviving Chromium child.

Final checks: the full non-browser regression run passed 1,779 tests, with 11
browser-marked tests deselected. Twenty focused preview/clock checks also passed
after unifying the timeline clock (including 24 fps and 30000/1001 unit cases).
The Studio, source-authoring and core-editor browser workflows passed. Lint,
source/wheel builds, and a fresh installed-wheel MCP/guide/tracking smoke check
passed. Package manifests and lockfiles were not changed.

## Limits of the evidence

No provider credentials or user footage were available for a scored semantic
video-understanding experiment. The timestamps/colors and transcript paging use
known synthetic ground truth; the transcript is supplied metadata, not an ASR
accuracy result. Contact sheets are bounded uniform samples, not scene detection
or semantic indexing. Vision-capable models interpret them; more frames or a
narrower range are needed for brief events. Actual billed token use and model
editing accuracy remain to be measured with the chosen provider and footage.

GPU throughput, long-form workloads, Windows/macOS runtime behavior and human
usability studies were not measured. Existing compatibility interfaces remain
available instead of deleting functionality that stored projects may need.
The architecture is substantially simpler on the default path, but the legacy
render migration and optional service implementations are not a complete rewrite.

The subsequent [ten-second explainer workflow](OPENEDIT_EXPLAINER_WORKFLOW.md)
records a real editable animation, original audio, browser preview/reopen,
verified final exports, and additional fixes found while using the application.
The native OpenCode MCP connection and transport mutation test pass. A live
model request is still blocked by this cloud environment's destination policy;
the workflow log distinguishes that limitation from application defects and
authoring mistakes.
